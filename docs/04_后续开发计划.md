# 后续开发计划

## 1. 12 周路线

| 周次 | 目标 | 交付物 |
|---|---|---|
| 1–2 | 跑通并理解 Demo；录 3 个真实课程视频 | 基线报告：耗时、显存、片段质量 |
| 3–4 | faster-whisper 已完成；完善 OCR 版面分析并接入可选 VLM 画面语义 | 无字幕课程也能跑；画面证据进入评分 |
| 5–7 | 标注 20–30 个课程视频；训练融合头 | 三组消融：纯文本 / +音频 / +视觉 |
| 8–9 | 章节质量与交互优化 | 关键词检索、片段增删、模板保存 |
| 10 | 端侧验证 | ONNX/TensorRT；Orin Nano 或笔记本 GPU 时延/显存 |
| 11–12 | 参赛材料 | 演示视频、BP 修订、评测报告、答辩 PPT |

## 2. 数据与标注

- 来源：本校课程录播（需授权/脱敏）、公开慕课、EDUVSUM/TVSum/SumMe；
- 标注：每个视频标 5–10 个“必看片段”及章节标题；
- 弱监督：用户在界面里的保留/删除操作作为偏好信号；
- 目标：先做 20–30 个视频的小闭环，不追求大规模。

## 3. 模型升级

优先级从高到低：

1. **VLM 场景证据**：Qwen-VL 等模型生成带时间戳的画面描述（已实现可选后端）；
2. **Chinese-CLIP 关键帧向量**：替换手工视觉特征并支持语义检索；
3. **轻量融合头**：逻辑回归/MLP，输入三模态分数 + 时长 + 关键词数；
4. **本地 LLM 润色**：Qwen/GLM 生成章节摘要，失败自动回退模板。

不建议当前阶段从头训练视频大模型：数据、算力和周期都不匹配。

## 4. 评测指标

| 维度 | 指标 | 当前 | 目标 |
|---|---|---|---|
| 内容 | 关键片段召回 | 未测 | ≥ 70% |
| 内容 | 摘要冗余率 | 未测 | ≤ 20% |
| 结构 | 章节标题可读性 | 人工 | ≥ 80% 可接受 |
| 效率 | 1 小时课程处理时间 | 未测 | ≤ 5 min（CPU） |
| 效率 | 峰值内存 | 未测 | ≤ 8 GB |
| 体验 | 交互响应 | < 1 s | < 1 s |

## 5. 端侧部署

- 先在笔记本 RTX / CPU 上验证；
- 再迁移到 Jetson Orin Nano 8GB（不要用 4GB 的 Jetson Nano）；
- 优化手段：1–2 FPS 采样、ONNX/TensorRT、INT8 量化、分段推理；
- 指标口径写清楚：是“端到端处理倍率”还是“单帧推理 FPS”，不要混用。

## 6. 产品化

- 任务队列 + 对象存储 + 用户/课程空间；
- 教师端：上传课程、编辑章节、发布摘要；
- 学生端：按章节复习、关键词定位、收藏片段；
- API：对接 LMS/录播平台；
- 私有化：学校内网部署，数据不出校。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 真实课程数据不足 | 先用公开数据集 + 合成数据，逐步替换 |
| 多模态增量不明显 | 做消融，若视觉无增益就调整特征/场景 |
| 长视频太慢 | 自适应抽帧、分段缓存、先字幕后 ASR |
| 端侧跑不动 | 降低采样率、模型量化、只保留关键帧分支 |
| 被质疑“套壳” | 明确列出参考项目与自研模块，展示消融和交互 |
