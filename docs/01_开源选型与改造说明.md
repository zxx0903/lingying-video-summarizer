# 开源选型与改造说明

## 1. 结论

我们没有直接 fork 一个“大而全”的项目，而是采用：

| 角色 | 项目 | 使用方式 |
|---|---|---|
| 工程参考 | OpenClip（MIT） | 参考其“下载→转写→分段→LLM 评分→剪辑”的流水线拆分与中文 ASR 路由 |
| 算法参考 | EDUVSUM（MIT） | 参考教育视频中音频、视觉、文本三类特征的融合与重要片段识别 |
| 任务/评测参考 | MMSum（Apache-2.0） | 参考多模态摘要的任务定义、数据集组织与评测思路 |
| 产品交互参考 | Koma（无 License） | 只参考“摘要/章节/关键帧/字幕/导出”的信息架构，不复制代码 |
| 竞品参考 | NVIDIA VSS（Apache-2.0） | 用于竞品分析和系统架构对照，不作为 Demo 底座 |

这样做的原因：

1. **周期可控**：大创团队 4 人、以本科低年级为主，必须避免一上来就接企业级 GPU 微服务。
2. **能讲清楚贡献**：底座只提供工程骨架，核心评分、场景覆盖、交互和大纲对齐由我们实现。
3. **许可证干净**：MIT / Apache-2.0 可修改、可商用；Koma 没有 License，只做交互参考。

## 2. 选型矩阵

| 项目 | 上手难度 | 中文 | 多模态 | 许可证 | 结论 |
|---|---|---|---|---|---|
| OpenClip | 低 | 强 | 弱（可扩展） | MIT | 工程参考，最合适 |
| EDUVSUM | 中 | 中 | 强 | MIT | 算法参考 |
| MMSum | 中高 | 弱 | 强 | Apache-2.0 | 任务/评测参考 |
| Koma | 中 | 中 | 中 | 无 | 只参考产品交互 |
| AutoClip | 中 | 强 | 弱 | MIT | 可选前端/合集参考 |
| NVIDIA VSS | 高 | 弱 | 强 | Apache-2.0 | 竞品，不适合做底座 |
| AI YouTube Shorts | 低 | 弱 | 弱 | MIT | 方向偏英文竖屏二创，不采用 |

## 3. 从 OpenClip 借鉴了什么

OpenClip 的 README 与目录体现出较好的分层：

- 下载 / 字幕获取 / 本地 ASR / LLM 分析 / 片段渲染相互解耦；
- 中文优先 Paraformer、英文 Whisper 的路由；
- 支持 user intent（自然语言描述想要的高光）；
- 有片段边界修正和二次编辑。

我们在 `lingying/` 中重新实现了适合教育场景的流水线：

- 不依赖它的 Web 前端和 LLM 供应商配置；
- 用我们自己的多模态评分替代“纯转写 + LLM 打分”；
- 增加场景/大纲对齐、章节生成、关键帧拼图、时间轴、交互式重渲染。

## 4. 从 EDUVSUM / MMSum 借鉴了什么

- **EDUVSUM**：教育视频的重要片段不只由语音决定，视觉（幻灯片、板书）与文本
  （字幕、课件）都应参与；我们据此设计了文本/音频/视觉三路特征与动态门控。
- **MMSum**：多模态摘要需要同时考虑“选哪些片段”和“如何生成摘要/缩略图”；
  我们因此在输出层同时提供片段、关键帧和结构化文本，而不是只给一段文字摘要。

两者都是研究代码，我们没有直接加载它们的模型权重，也没有把它们的训练脚本
接进 Demo；当前是“按同样的任务分解，用轻量特征实现一个可运行版本”。

## 5. 我们新增了什么

| 模块 | 文件 | 说明 |
|---|---|---|
| 多模态特征 | `lingying/fusion.py`、`audio_features.py`、`visual_features.py` | 三路特征 + 可靠性门控 |
| 场景覆盖选择 | `lingying/select.py` | 每个场景/章节先选代表，再按分数补足，最后裁剪到目标时长 |
| 大纲对齐 | `lingying/summarize.py`、`pipeline.py` | 支持同名 JSON 大纲，章节标题可控 |
| 章节与摘要 | `lingying/summarize.py` | 模板生成 + 可选 LLM 润色 |
| 渲染与可视化 | `lingying/render.py` | 片段、关键帧拼图、时间轴、摘要 SRT |
| Web 交互 | `lingying/app.py` | 上传、参数、片段增删、关键词检索、导出 |
| 演示数据 | `scripts/make_demo.py` | 自动生成 6 页中文课程 + TTS + SRT |

## 6. 许可证与答辩表述

- OpenClip / EDUVSUM：MIT，保留版权声明即可。
- MMSum：Apache-2.0，保留 NOTICE/License。
- Koma：仓库未标注 License，**不要复制其代码**，只参考交互。
- 答辩时建议表述为“参考了 OpenClip 的工程分层、EDUVSUM/MMSum 的多模态摘要思路，
  在此基础上实现了面向中文教育场景的轻量融合与交互原型”，不要声称“完全自研所有模块”。
