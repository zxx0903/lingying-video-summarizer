# 视觉语义增强设计

## 1. 目标

在字幕、语音和 OCR 之外，为画面生成可检索的语义证据，使课堂实拍、实验演示、
板书和无字幕视频也能形成内容摘要，而不是只按边缘、颜色和运动打分。

## 2. 数据流

```text
字幕 / Whisper / OCR ──────────────┐
                                  ├─ 多模态证据
场景关键帧 → VLM 画面描述 ─────────┘
                                  ↓
                        关键词、模板先验与评分
                                  ↓
                        章节、摘要、片段和关键帧
```

每个 VLM 证据包含：

```json
{
  "time": 125.0,
  "description": "讲师正在终端运行自动化脚本",
  "objects": ["讲师", "投影屏幕", "笔记本电脑"],
  "actions": ["运行脚本"],
  "on_screen_text": "python demo.py",
  "content_type": "code",
  "confidence": 0.86,
  "backend": "qwen-vl"
}
```

## 3. 后端

### 3.1 本地 Qwen-VL

- 默认模型：`Qwen/Qwen2.5-VL-3B-Instruct`
- 默认 4-bit 量化，适合 8 GB 显存笔记本
- 只处理场景代表帧，默认最多 80 帧
- 结果缓存为 `vlm_frames.json`，中断后可复用

安装：

```powershell
.\scripts\setup.ps1 -Vlm
```

将本地模型目录写入 `runtime/vlm_model_path.txt`，或设置环境变量
`LINGYING_VLM_MODEL`。

### 3.2 OpenAI 兼容视觉接口

适用于 Ollama、LM Studio、vLLM 或校内模型服务：

```text
vlm_backend = openai-compatible
vlm_base_url = http://127.0.0.1:11434/v1
vlm_model = <本地部署的视觉模型名称>
```

## 4. 证据与摘要约束

- VLM 只能描述可见内容，提示词禁止猜测身份、地点和意图；
- 输出带时间戳，时间段与原始视频对应；
- 摘要通过 `semantic_text` 同时使用语音、OCR 和画面描述；
- 无语音时，画面证据仍可参与关键词、章节和摘要；
- 所有来源均不可用时，系统明确提示无法可靠总结，不编造内容。

## 5. 运行条件

- 本地 Qwen-VL：Python 3.10/3.11、PyTorch、Transformers、CUDA 可选；
- 推荐 NVIDIA GPU 显存 8 GB 以上；
- 模型与依赖下载量取决于具体模型，必须在下载前确认；
- CPU 快速模式仍支持字幕、Whisper 和 OCR；
- VLM 增强模式较慢，建议单独报告处理时延，不与纯 CPU 基线混用。

## 6. 验收

至少覆盖以下四类视频：

1. 有字幕课程；
2. 无字幕但有清晰语音；
3. 无语音但屏幕文字清晰；
4. 无字幕、无语音或文字较小，需要画面语义理解。

对第四类视频，要求每个入选章节至少存在一个 VLM 画面证据，并在结果 JSON 中
保留时间戳、描述和置信度。
