# 答辩与演示脚本

## 1. 一句话定位

“灵影速览”是一个面向中文课程视频的**轻量多模态摘要原型**：
不只依赖语音转写，而是让**字幕文本、语音能量、画面信息**共同决定哪些片段值得看，
并输出章节、片段、关键帧和可编辑的摘要。

## 2. 3 分钟演示流程

### 0:00–0:30 痛点

- 一节 45 分钟课程，学生复习时要重新拖动进度条；
- 现有工具大多只做“语音转文字 + 大模型总结”，画面里的 PPT、板书、实验演示被忽略；
- 我们要解决的是“**从长视频里找到值得看的那几分钟**”，而不只是生成一段文字。

### 0:30–1:40 现场演示

1. 打开 Web 界面，选择「使用演示课程」；
2. 点击「开始生成摘要」，等待约 5 秒；
3. 展示：
   - 6 个章节、每章时间戳；
   - 右侧摘要预览；
   - 「片段与调整」里勾选/取消片段并重新渲染；
   - 「关键帧」拼图；
   - 「时间轴」里橙色入选片段。

讲解词：

> 系统先按字幕停顿切分片段，再分别计算文本关键词、教学提示词、语音能量和画面信息量，
> 通过动态门控融合成重要度分数。选择时不是简单取 Top-K，而是先保证每个章节/幻灯片
> 都有代表片段，再补足时长，所以不会出现“摘要全在前 3 分钟”的问题。

### 1:40–2:30 技术亮点

- **三模态**：文本、音频、视觉都有独立特征和权重；缺模态自动降权。
- **教学先验**：重点、注意、总结、作业等词会加分，符合课程结构。
- **场景覆盖**：每个章节先选代表，解决长视频摘要的“时间塌缩”。
- **轻量**：纯 CPU，2 分钟视频约 4.6 秒，约 28× 实时；不依赖 GPU。
- **可交互**：保留/删除片段、关键词检索、重新渲染、导出 SRT/JSON/片段。

### 2:30–3:00 边界与计划

- 这是原型，真实课堂数据和系统评测是下一步；
- 计划接入 CLIP/中文 CLIP 语义特征、Whisper 无字幕转写、Jetson Orin 端侧部署；
- 目标场景：高校课程复习、K12 课堂回看、企业培训。

## 3. 评委可能追问

**Q1：这和“Whisper + GPT 总结”有什么区别？**

> 那类方案主要看转写文本，画面信息不参与决策。我们的评分里视觉和音频是独立模态，
> 并且做了消融接口；对于 PPT 翻页、板书、实验演示多的课程，纯文本会漏掉关键画面。

**Q2：你们的多模态融合是不是拼凑？**

> 当前是轻量、可解释的可靠性门控：每个模态先归一化，再按可用性调整权重，
> 不是简单平均。下一步会用标注数据训练门控参数，并做三组消融证明增量。

**Q3：为什么不用 CLIP/BERT？**

> 这一版优先保证 CPU 可跑和答辩现场稳定；视觉分支已经按“模态分数”抽象，
> 后续可以直接把手工特征替换成 Chinese-CLIP 向量，不需要改上层选择逻辑。

**Q4：2 分钟视频说明不了问题，1 小时课程行不行？**

> 当前只验证了流程。长视频需要重新评测：抽帧会自适应降采样，选择算法按场景覆盖，
> 但耗时、覆盖率和章节质量都要在真实课程上测。我们不会把 2 分钟的数字外推到 1 小时。

**Q5：你们的创新点是什么？**

> 不是发明 Whisper 或 CLIP，而是：
> （1）面向中文教育场景的三模态可靠门控；
> （2）场景/大纲覆盖约束的片段选择；
> （3）可交互的“机器初筛 + 人工调整”闭环；
> （4）纯 CPU 的轻量实现。

**Q6：数据从哪里来？**

> Demo 用自动生成的合成课程验证流程；下一步采集/脱敏真实课程，并请助教标注
> “必看片段”。也会用 TVSum/SumMe/EDUVSUM 做公开基准对比。

**Q7：商业模式？**

> 先做工具型产品：教师/机构按课程包或订阅付费；API 面向 LMS/录播平台；
> 端侧版本面向隐私敏感的学校私有化部署。当前阶段先把 Demo 和评测做扎实。

**Q8：为什么不用 NVIDIA VSS？**

> VSS 是企业级 GPU 方案，适合作为竞品和架构参考；我们的目标是低成本的课程场景，
> 所以选择纯 CPU、可离线、易部署的路线。

## 4. 不要说的话

- 不要说“国内领先/填补空白”——开源里已有大量同类项目；
- 不要说“Jetson Nano 上 30 FPS 跑完整链路”——硬件和模型规模都不支持；
- 不要说“完全自研所有算法”——要如实说明参考了 OpenClip/EDUVSUM/MMSum；
- 不要把 2 分钟合成视频的指标包装成真实课堂效果。
